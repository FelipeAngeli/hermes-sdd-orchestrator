# Testing

[Docs index](../README.md) · Related: [Maintaining the docs](../maintaining-docs.md), [Contracts and schemas](contracts-and-schemas.md), [Skill and installer](skill-and-installer.md)

**Files:** `tests/*` (skill suite, at the repository root) and `orchestration/tests/*` (installed controller suite, shipped to every project).

Both suites use `unittest` and need no external services. The bounded-run tools additionally need `jsonschema`. CI runs both suites on every push and pull request (`.github/workflows/ci.yml`). Before the suites, CI checks out hermes-agent commit `4e9d3c713a3e3d47319ab18a8d8dfade5665270d` and requires the complete distributable skill to receive a `SAFE` verdict from `skills-guard-v5` through `tools/check_skill_security.py`. It then scans and tests the two [store review guardians](store-review-guardians.md) (`skills/release/*`) the same way.

The root suite is behavioral at its executable boundaries: installer, documentation-sync and release scenarios run their public CLIs against temporary Git repositories and assert observable files, output, commits and tags. Documentation and agent briefs are treated as published contracts; their tests assert metadata, catalogues, safety boundaries and decision concepts without importing production helpers or mirroring internal control flow.

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
python3 -m unittest discover -s skills/orchestrate/sdd-orchestrator/templates/.hermes/orchestration/tests -p 'test_*.py'
```

### Live OpenCode tests (opt-in, paid)

Tests that call the paid OpenCode model never run by default: `SDD_OPENCODE_LIVE` defaults to `0`, and only the exact value `1` turns them on. The switch is read only by the repository harness `tests/test_controller_opencode_e2e.py`; the shipped `orchestration/tests/test_opencode_isolation.py` never reads the process environment (its worker environment is built from fixed values, so the Hermes skills scanner finds no environment access), and its paid cases stay skipped unless that harness sets `SETTINGS["live"]`. With the switch on, the harness runs its end-to-end demand **and** re-runs the isolation suite's paid cases (`LiveOpencodeIsolationTests`). It needs the real `codex`, `opencode` 1.18.34 and the logged-in OpenCode account; `SDD_OPENCODE_TEST_MODEL` overrides the model and `SDD_OPENCODE_E2E_REPORT` writes the run report.

```bash
SDD_OPENCODE_LIVE=1 python3 -m unittest tests.test_controller_opencode_e2e -v
```
